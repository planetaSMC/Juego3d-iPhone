# V20.1 · Corrección de compilación de Core Motion

## 1. Causa exacta

El workflow `iOS app V20 (RASMATIC VR)` falló en Xcode 16.4 / iPhoneOS 18.5
con:

```
type 'CMAttitudeReferenceFrame' has no member 'xArbitrary'
```

El archivo `ios/RasmaticLugar3D/HeadTrackingBridge.swift` usaba un valor que
**no existe** en Core Motion:

```swift
frames.contains(.xArbitraryZVertical) ? .xArbitraryZVertical : .xArbitrary
```

`CMAttitudeReferenceFrame` solo define cuatro marcos:

| Valor real | Uso |
|---|---|
| `.xArbitraryZVertical` | Eje Z vertical, rumbo relativo al arranque, sin magnetómetro |
| `.xArbitraryCorrectedZVertical` | Igual, corregido con magnetómetro |
| `.xMagneticNorthZVertical` | Norte magnético |
| `.xTrueNorthZVertical` | Norte verdadero |

No hay un `.xArbitrary` genérico. El fallback era inválido y rompía la
compilación de Swift.

### Segundo error detectado por Actions

El primer intento de corrección quitó `.xArbitrary`, pero escribió el marco
magnético en minúscula. Xcode 16.4 lo rechazó:

```
type 'CMAttitudeReferenceFrame' has no member 'xmagneticNorthZVertical'
```

El nombre correcto es **`.xMagneticNorthZVertical`** (M mayúscula). Se corrigió
en el commit `b008e34`; ese es el commit que compiló en verde.

## 2. Corrección

Se consulta `CMMotionManager.availableAttitudeReferenceFrames()` y se elige el
primer marco realmente disponible, en este orden:

1. `.xArbitraryZVertical` (preferido: estable en interiores, sin magnetómetro).
2. `.xArbitraryCorrectedZVertical`.
3. `.xMagneticNorthZVertical`.
4. `.xTrueNorthZVertical`.

Si el equipo tiene `deviceMotion` pero no ofrece ningún marco, se informa
`"Sin marco de referencia"`, **no se inicia** la sesión y no se simula nada.

```swift
private static func referenceFrame(
    available: CMAttitudeReferenceFrame
) -> CMAttitudeReferenceFrame? {
    let preferred: [CMAttitudeReferenceFrame] = [
        .xArbitraryZVertical,
        .xArbitraryCorrectedZVertical,
        .xMagneticNorthZVertical,
        .xTrueNorthZVertical
    ]
    return preferred.first { available.contains($0) }
}

func start() {
    guard !running else { return }
    guard motion.isDeviceMotionAvailable else {
        sendStatus(available: false, name: "Sin giroscopio")
        return
    }
    guard let frame = HeadTrackingBridge.referenceFrame(
        available: CMMotionManager.availableAttitudeReferenceFrames()
    ) else {
        sendStatus(available: false, name: "Sin marco de referencia")
        return
    }

    running = true
    lastOrientation = ""
    lastStatus = ""

    motion.deviceMotionUpdateInterval = HeadTrackingBridge.interval
    motion.startDeviceMotionUpdates(using: frame, to: .main) { ... }
}
```

También se actualizaron los comentarios del archivo para que digan
“RASMATIC VR” en vez de “app Head Tracking”.

## 3. Qué NO cambia

- Head Tracking sigue activo (`RASMATIC_HEAD_TRACKING` intacto).
- Se sigue usando Core Motion real, no una simulación.
- yaw, pitch, roll, calibración, recentrado, sensibilidad, suavizado,
  respuesta, inversión y sincronización con Windows no cambian.
- No se toca el juego, la farmacia, el mando Bluetooth, el joystick táctil ni
  el bundle `com.rasmatic.lugar3d`.
